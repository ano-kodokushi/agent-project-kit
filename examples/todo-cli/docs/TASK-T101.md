# T-101 · 清单标题加横幅前缀

| | |
|---|---|
| **难度 / 档位** | L0 / 机械活 |
| **依赖** | — |
| **inScope** | `src/format.js`、`test/run.js`（**仅限下面点名的 2 条期望值**） |
| **outOfScope** | `AGENTS.md`、`docs/**`、其它测试断言 |

**goal**：`formatHeader(n)` 的输出改为以 `== ` 起头（例如 `== 待办清单（3 项）`），
小计数字与其它格式一律不变。

**为什么**：用户反馈清单标题在一堆输出里不够显眼，希望有个视觉分隔。

---

## 本卡真正的考点：找全受影响的期望值

**初始状态 = `FAIL 1 项（通过 6 项）`，退出码 1。改完必须 `PASS 7/7`。**

失败的那条是 `formatHeader 带横幅前缀`。但要让它变绿，光改实现**不够**——
`formatList` 的期望值是**多行字符串**，标题**内嵌在首行里**，
所以那条既有断言必须**同步**更新，否则它会从"通过"变成"失败"。

> ⚠️ **本卡最容易踩的坑**：只改 `src/format.js` 就交差，于是
> `formatList 首行是标题、其后逐条` 开始报错。**改行为前先搜一遍所有写死了旧输出的断言。**

允许的改动**只有两处**：

1. `src/format.js`：`formatHeader` 的返回字符串加 `== ` 前缀
2. `test/run.js` · `formatList 首行是标题、其后逐条`：期望值的**首行**加 `== `

**除以上两处，其它断言一个字都不许动。** 尤其不许删断言、不许放宽成 `includes`。

## 验收命令

```bash
node test/run.js
```

## 通过标准

- 输出 `PASS 7/7`，退出码 **0**
- **断言条数仍是 7**（删掉任何一条都算作废）

## 反作弊

`formatItem` 的三条断言、`formatList` 空清单提示、`formatHeader 单行输出`
这几条必须**原样通过** —— 只加前缀，不许顺手改别的。
